15 May 2026

Implemented a new fix for blades that are split across the +pi/-pi boundary created through the use of arctan2 to convert to cylindrical coordinates. Tested this on a full-annulus set of identical blades and it works, all passage STLs are correclty generated.

In addition, I modified the framework for creating passage meshes to support multiple passages in general, and added an example script that creates 2 passages and joins them with mergeMeshes and stitchMesh -integral.

Current issues/features to deal with:

1. Need to add one more cylindrical-coordinates geometry check: make sure that "blade1" is actually at lower theta-coordinates than "blade 2" after ensuring neither is split across the +pi/-pi boundary.

2. Ran into an issue where LE and TE are not identical between the 2 blades of each passage from NAX (for aperiodic blade rows). First workaround was to just loosen tolerance on this. Turns out this is not really important for surface generation. Surfaces generate OK. However I realized there is an issue with the grid parameters (passageParameters) -- consistent grading parameters and numbers of axial cells are not guaranteed because of the fact that the distances from inlet to LE and outlet to TE are not exactly the same for each passage. Other than enforcing LE and TE to be the same for all passages as a pre-processing step, the best way I can see for dealing with this is to run as it is currently, and then reconcile the discrepancies in a 2nd "clean-up" pass at the end before going to generate meshes with blockMesh.
